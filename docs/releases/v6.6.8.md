## Navigation menus

- Reorganised the inbox conversation overflow menu from four groups into six — Tasks, Contact, Conversation, Tools & notifications, Panels and Danger zone — so each group populates independently. Submenus keep their existing overlay behaviour.

## Role-based access control

- Enforced the `inbox.reply` permission in the message composer. The key existed in the permission catalogue but was read by no application code, so a member without reply rights could still send messages. The composer now renders a read-only notice instead of the input, and the submit handler early-returns so keyboard shortcuts cannot bypass it.
- Mapped the `manager` workspace role to the seeded `manager` permission role. `_system_role_for_workspace_role()` had no branch for `manager`, so it returned `NULL`; callers treat a `NULL` mapping as "no role to assign" and skip the `user_role_assignments` insert entirely, leaving every manager with zero permissions and an almost-empty sidebar. Includes a backfill for members already affected.
- Gated high-risk destructive and outbound controls on their permission keys across contacts, companies, deals, campaigns, team and workspace surfaces — `contacts.delete`, `companies.delete`, `deals.delete`, `campaigns.send`, `campaigns.delete`, `members.invite` and `members.remove`. Each control is hidden or disabled and its mutation handler re-checks the permission, so a hidden button cannot be bypassed programmatically.
- Added a `useCanAct()` helper that treats an unresolved permission set as permitted, because `usePermissions()` reports an empty set while loading and before an active organisation resolves. Only a resolved negative blocks an action, so legitimate users are never locked out mid-load.
- Added a single route-level permission gate around the authenticated outlet, so reaching a page by typing its URL is now checked the same way as clicking its (hidden) sidebar link. Required permissions are derived from the `permission` field already present on each navigation entry, with nested paths inheriting their parent's gate and the least-restrictive entry winning where several entries share a path. The gate fails open while permissions, the super-admin check or the active organisation are still resolving.

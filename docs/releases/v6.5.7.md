## Claude session

Session work: Dashboard nav naming, Global Search UX and a deep-link bug fix, per-category Global Search pagination, landing page CTA styling, a new Super Admin "Create Tenant" flow, Inbox composer sizing, a double-header cleanup in the conversation view, and an inbox scroll-position bug fix.

### Navigation

- Renamed the sidebar group labelled "Workspace" (which only ever held Dashboard and Global Search) to "Dashboard" — `src/components/app/nav-config.ts`.

### Global Search

- Moved active filter chips and the "Clear" button out of the main search bar row into their own row below it, left-aligned, separated by a dashed top border — `src/routes/_authenticated/global-search.tsx`.
- Swapped the "Clear" button and the results-count/took-ms indicator: Clear now sits top-right next to the category picker, results count moved to the bottom filter row, right-aligned.
- **Fixed a deep-link bug**: clicking a "Messages" search result opened the Inbox to "Select a conversation" instead of the actual conversation, because the generated link used the query param `conversation` while the Inbox route only reads `conversationId`. Fixed in both search backends — `src/lib/search/omnichannel-search.functions.ts` (the one actually used by `/global-search`) and `src/lib/search/global-search.functions.ts` (used by the separate `/search` route).
- **Added pagination** to single-category result views (Messages, Deals, Invoices, Tasks, Campaigns, Knowledge, etc.): server-side range-based paging via a new `page` param on `omnichannelSearch`, with `hasMore`/`pageSize` returned to the client; Previous/Next controls render under the active category's results and reset to page 1 on query/category/filter change. The "All categories" overview is unaffected (still a mixed top-hits preview, not paginated). Contacts-derived (customers/phone/emails) and attachment-derived (media/voice/documents) categories page approximately, since each group is split client-side from one shared query.

### Marketing site

- Landing page "Sign in" button changed from the `ghost` Button variant to `outline` so it shows a visible border, matching the bordered look requested — `src/routes/index.tsx`. (An earlier pass edited `src/components/app/marketing-shell.tsx`'s Sign in link styling too, but that component isn't the one rendered on the actual landing page header.)

### Super Admin — Tenant Management

- Added a **Create Tenant** flow: a new `createTenant` server function (`src/lib/admin/tenants.functions.ts`) and a dialog on the Tenant Management page (`src/routes/_authenticated/_super-admin.admin.workspaces.tsx`) that creates an `organizations` row, an `organization_members` owner row, a first `workspaces` row and a `workspace_members` owner row in sequence (rolls back the org/workspace insert on partial failure).
  - **Constraint**: the owner email must already belong to an existing registered user (same rule `transferOwnership` already enforces) — this flow does not create new user accounts or send signup invites.

### Inbox

- **Message composer sizing**: increased the textarea's vertical padding (`py-2` → `py-3`) for a less cramped feel; height and horizontal padding left as originally designed — `src/components/app/inbox/message-composer.tsx`.
- **Removed the double header in the conversation view**: the conversation screen had two stacked header bars (the main contact/actions header, plus a slim "channel bar" directly under it showing the channel switcher and priority badge), which squeezed the message area. The channel switcher and priority badge now live in the main header, to the left of the AI/layout/more action icons; the separate channel subheader bar (and its now-unused typing/online indicator) was removed — `src/components/app/inbox/conversation-header.tsx`, `src/components/app/inbox/conversation-window.tsx`.
- **Fixed conversation scroll-to-bottom on open**: opening a conversation from the list sometimes left the message view scrolled to roughly the middle of the thread instead of jumping to the latest message. Two compounding causes: (1) the conversation view component is reused across conversation switches (only the `conversation` prop changes), and a ref tracking the previous message count wasn't reset between conversations, so the "new content, scroll to bottom" check could silently miss the switch — now resets on `conversation.id` change; (2) even after that fix, attachments (images) inside messages load asynchronously and grow the content height *after* the initial scroll-to-bottom already ran, leaving the view short of true bottom — a `ResizeObserver` on the message list now re-pins to the latest message whenever content height changes, as long as the user hasn't scrolled up to read older messages (tracked via a scroll listener) — `src/components/app/inbox/conversation-window.tsx`.

## Codex session

### Team member directory

#### Fixed

- Fixed invited workspace members appearing as **"Unnamed"** with a missing avatar in **Settings → Team → Directory**.
- The member directory now loads workspace-member profile data through a dedicated, workspace-scoped database function instead of querying `profiles` directly.

#### Root cause

- The `profiles` table's row-level security policy only allowed users to read their own profile.
- Workspace owners could read another user's `workspace_members` row, but the related name, avatar, email, and activity fields were unavailable. The UI therefore fell back to "Unnamed" and the placeholder avatar.

#### Implementation

- Added the `get_workspace_member_directory(_workspace_id uuid)` security-definer RPC.
- Restricted the RPC to authenticated users and verified that the caller belongs to the requested workspace before returning directory data.
- Updated `useWorkspaceMembers()` to use the new RPC.
- Added an authenticated server-function fallback so the UI does not depend on the RPC migration being deployed first.
- The server function verifies the caller's workspace membership before reading member identities with the guarded service-role client.
- Added Auth metadata/email fallbacks for incomplete profile rows (`full_name`, `name`, `avatar_url`, `picture`, and email username).
- Added regression tests covering workspace scoping, caller membership checks, RPC permissions, and Auth identity fallbacks.

#### Changed files

### Centralized prebuilt Cloudflare deployment

- Split Cloudflare build and deployment into two explicit phases so the production/origin server never compiles the application.
- `npm run build` performs the Cloudflare Vite/Nitro build locally and produces the complete `.output/` artifact.
- `npm run deploy:cloudflare` reads the Worker, domain and zone from local `.env`/`.env.local`, then uploads the existing artifact without rebuilding it.
- Added `scripts/deploy-cloudflare.mjs`, which selects the Cloudflare Worker by name, binds exactly one requested custom domain, rejects invalid targets, and removes its temporary Wrangler configuration after deployment.
- Removed the per-domain Wrangler configuration pattern; clients can deploy independent copies without adding another configuration file to the repository.
- Updated the Cloudflare GitHub workflow to show separate build and prebuilt-upload steps. The build runs on the CI runner, never on the production application server.

### Payment-link currencies

- Replaced the free-text currency field in **Commerce → Payment Links → New payment link** with a dropdown populated from the currencies enabled in **Super Admin → Platform Settings**.
- The dropdown only shows currencies that are both enabled by the administrator and supported by the selected payment provider.
- Added server-side validation so a disabled or provider-incompatible currency cannot be submitted by bypassing the user interface.
